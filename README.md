# Охота кофе: мобильное приложение Камбаршоп

Приложение для iOS и Android: магазин кофе и сладкой гастрономии, меню кофейни с заказом готовых напитков, ремонт кофемашин KAMBARSERVICE. Каталог, цены и остатки берутся из 1С, заказы и заявки на ремонт записываются в 1С и передаются во внутреннее приложение компании.

## Состав

| Папка | Что внутри |
|---|---|
| `apps/mobile` | Приложение: React 19 + Vite, нативные оболочки Capacitor 8 (`ios/`, `android/`) |
| `apps/api` | Сервер: Fastify 5, PostgreSQL (Drizzle ORM), обмен с 1С, ЮKassa, SMS, push |
| `packages/shared` | Общие типы, схемы проверки данных, расчёт денег |
| `docs/` | Интеграция с 1С, API для внутреннего приложения, выпуск в сторы |

## Как это устроено

```
 Телефон (iOS / Android)
        │  HTTPS, JSON
        ▼
 Сервер apps/api ─────────────► ЮKassa (онлайн-оплата)
   │   ▲    │ очередь с повторами
   │   │    ├────────────────────► 1С: заказы, заявки на ремонт
   │   │    └────────────────────► Внутреннее приложение (вебхуки)
   │   └─ каждые 10 минут ◄─────── 1С: каталог, цены, остатки
   ▼
 PostgreSQL
```

1. Сервер раз в 10 минут забирает из 1С номенклатуру, характеристики, цены и остатки и собирает снимок каталога. Приложение читает снимок, поэтому работает быстро и не зависит от доступности 1С.
2. Цены в заказе пересчитываются на сервере, цены с телефона не принимаются.
3. Заказ и заявка на ремонт сначала сохраняются в базе, затем уходят в 1С и во внутреннее приложение через очередь. Если 1С недоступна, отправка повторяется до 25 раз с растущей паузой, заказ не теряется.
4. Внутреннее приложение меняет статусы через `/internal/v1`, клиент получает уведомление в приложении и push.

## Быстрый старт (разработка)

Нужен Node.js 22+.

```bash
npm install
npm run dev -w @kbs/api        # сервер на http://localhost:8080, демо-каталог, база PGlite в .data/
npm run dev -w @kbs/mobile     # приложение на http://localhost:5173
```

В режиме разработки 1С не нужна (`ONEC_MODE=mock`), SMS не отправляются: код входа подставляется автоматически.

Проверки:

```bash
npm run typecheck
npm test                       # сценарии API: вход, заказ, очередь в 1С, ЮKassa, внутреннее API
```

## Боевой запуск сервера

```bash
cp apps/api/.env.example apps/api/.env      # заполнить
POSTGRES_PASSWORD=... docker compose up -d --build
```

Миграции базы применяются при старте. Проверка 1С без запуска сервера: `npm run sync:1c -w @kbs/api`.

Сервер должен быть доступен по HTTPS (например, nginx или Caddy перед контейнером). Адрес указывается в `PUBLIC_URL` и при сборке приложения в `VITE_API_URL`.

## Сборка приложения

```bash
cd apps/mobile
cp .env.example .env            # VITE_API_URL=https://api.ваш-домен
npm run cap:sync                # сборка и копирование в ios/ и android/
npx cap open ios                # Xcode
npx cap open android            # Android Studio
```

Подробно о публикации: [docs/store-release.md](docs/store-release.md).

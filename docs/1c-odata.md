# Подключение 1С через OData

Режим `ONEC_MODE=odata`. Работает с типовыми конфигурациями (УТ 11, КА 2, ERP, УНФ) без доработок: используется стандартный интерфейс OData, который включается в самой 1С.

## 1. Включить OData в 1С

1. Опубликовать базу на веб-сервере (Apache или IIS) с флажком «Публиковать стандартный интерфейс OData».
2. В 1С: Администрирование, затем «Интернет-поддержка и сервисы», «Синхронизация данных», «Настройки стандартного интерфейса OData». Создать пользователя для обмена и отметить объекты:
   * Справочник «Номенклатура»
   * Справочник «Характеристики номенклатуры» (если используются вкусы, объёмы)
   * Регистр сведений «Цены номенклатуры»
   * Регистр накопления «Товары на складах» (если нужны остатки)
   * Документ «Заказ клиента» (запись заказов)
3. Проверить в браузере: `https://сервер/база/odata/standard.odata/Catalog_Номенклатура?$top=1&$format=json`

## 2. Настроить сервер

В `apps/api/.env`:

```
ONEC_MODE=odata
ONEC_BASE_URL=https://сервер/база/odata/standard.odata
ONEC_USER=пользователь_обмена
ONEC_PASSWORD=пароль
```

## 3. Заполнить соответствия в `apps/api/config/onec-odata.json`

Файл уже настроен на УТ 11. Обязательно заменить нулевые идентификаторы (`00000000-...`) на свои. Идентификатор (Ref_Key) любого объекта можно посмотреть запросом OData или в 1С через «Перейти по навигационной ссылке».

| Поле | Что указать |
|---|---|
| `items.rootGroupRefs` | Ref_Key групп номенклатуры, которые продаются в приложении. Пусто: весь справочник |
| `prices.priceTypeRef` | Ref_Key вида цен «Розничная» |
| `stock.warehouseRefs` | Ref_Key складов, остатки которых показывать. Пусто: все склады |
| `order.template` | Реквизиты нового «Заказа клиента»: организация, партнёр (розничный покупатель), контрагент, соглашение, склад, валюта |
| `order.post` | `true`: проводить заказ сразу, `false`: оставить записанным |

В шаблоне можно использовать подстановки: `{{number}}`, `{{date}}`, `{{deliveryType}}`, `{{phone}}`, `{{customerName}}`, `{{address}}`, `{{pickupPoint}}`, `{{paymentMethod}}`, `{{comment}}`, `{{total}}`, в строках товаров `{{lineNumber}}`, `{{itemRef}}`, `{{charRef}}`, `{{qty}}`, `{{price}}`, `{{sum}}`.

Заявки на ремонт в типовых конфигурациях хранить негде, поэтому в режиме OData они по умолчанию идут только во внутреннее приложение (`repair.enabled: false`). Если в базе есть свой документ для ремонта, его можно описать так же, как заказ.

## 4. Разложить товары по разделам приложения: `apps/api/config/catalog.json`

* `shop`: разделы магазина (молотый кофе, зёрна, дрип, чай, сиропы). Для каждого раздела перечисляются группы 1С по коду, наименованию или Ref_Key. Подгруппы попадают в раздел автоматически.
* `menu`: разделы меню кофейни. `presentation` задаёт кружку на экране заказа: `classic`, `author`, `cold`, `tea`, `lemonade`.
* `addons`: группа с добавками к напиткам (сахар, сироп, молоко). Цена добавки по объёму берётся из характеристик «250 мл», «350 мл», «450 мл».
* `products`: необязательное оформление карточек по коду номенклатуры: фото, подзаголовок, короткие факты, старая цена.

Фото кладутся в `apps/api/media`, в `catalog.json` указывается имя файла.

## 5. Проверить

```bash
npm run sync:1c -w @kbs/api
```

Команда покажет, сколько разделов и товаров получено из 1С. Товары без розничной цены в приложение не попадают.

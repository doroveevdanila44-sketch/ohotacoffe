# API для внутреннего приложения компании

Внутреннее приложение получает новые заказы и заявки и меняет их статусы. Клиент сразу видит изменения в приложении и получает push.

Адрес: `https://api.ваш-домен/internal/v1`. Каждый запрос с заголовком `X-Api-Key: <INTERNAL_API_KEY>`.

Суммы во всех ответах в копейках (`157000` = 1 570 ₽). Даты в ISO 8601.

## Заказы

| Метод | Путь | Описание |
|---|---|---|
| GET | `/orders?status=new&since=2026-11-01T00:00:00Z&limit=100` | Список, новые сверху |
| GET | `/orders/{id}` | Заказ, телефон и имя клиента, ссылка на документ 1С |
| POST | `/orders/{id}/status` | Сменить статус: `{ "status": "cooking" }` |

Статусы: `awaiting_payment` (ждёт онлайн-оплату), `new`, `accepted`, `cooking`, `on_the_way`, `ready_for_pickup`, `done`, `cancelled`.

Переходы: из `new` в любой рабочий статус или `cancelled`; дальше только вперёд. Попытка вернуть назад даст `409`.

## Ремонт

| Метод | Путь | Описание |
|---|---|---|
| GET | `/repairs?stage=diagnostics&limit=100` | Список заявок |
| PATCH | `/repairs/{id}` | Обновить этап, смету, мастера, срок |

```json
{
  "stage": "approval",
  "note": "Нашли износ помпы, согласуйте смету",
  "services": [
    { "title": "Диагностика", "price": 80000, "state": "done" },
    { "title": "Замена помпы", "price": 310000, "state": "pending" }
  ],
  "total": 390000,
  "readyBy": "2026-11-06T18:00:00+12:00",
  "masterName": "Алексей",
  "serial": "DL-5530-91274"
}
```

Этапы: `new`, `accepted`, `diagnostics`, `approval`, `repair`, `testing`, `ready`, `returned`, `cancelled`. Все поля необязательны, передавайте только изменившиеся.

| POST | `/catalog/sync` | Обновить каталог из 1С сейчас, не дожидаясь расписания |

## Вебхуки

Если задан `INTERNAL_WEBHOOK_URL`, сервер отправляет туда события POST-запросом:

```
X-KBS-Event: order.created
X-KBS-Signature: sha256=<HMAC-SHA256 тела запроса ключом INTERNAL_WEBHOOK_SECRET, hex>

{ "event": "order.created", "data": { ...заказ... }, "sentAt": "..." }
```

События: `order.created` (заказ подтверждён: оплачен онлайн или с оплатой при получении), `order.status_changed`, `repair.created`, `repair.updated`, `user.deleted`.

Проверяйте подпись перед обработкой. Ответ `2xx` означает, что событие принято; иначе сервер повторит отправку с паузой. Одно событие может прийти дважды, ориентируйтесь на `data.id`.
